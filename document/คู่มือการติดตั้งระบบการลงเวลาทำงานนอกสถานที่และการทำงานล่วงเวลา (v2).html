3. การติดตั้งฐานข้อมูล

3.1 สร้างฐานข้อมูลและนำเข้าโครงสร้าง (ติดตั้งใหม่เท่านั้น)

ใช้บัญชีผู้ดูแลฐานข้อมูลเฉพาะตอนติดตั้งเท่านั้น (ไม่ใช่บัญชีที่แอปพลิเคชันใช้งาน) ไฟล์ database/schema-mariadb.sql จะสร้างฐานข้อมูล worktime (utf8mb4) และคอลัมน์ employee.active ให้ครบ

mariadb -u <admin_user> -p < database/schema-mariadb.sql

หมายเหตุ: ห้ามใช้ database.sql สำหรับการติดตั้งใหม่อีกต่อไป (เป็น dump เก่าของ MySQL 5.5) และห้ามรัน schema ซ้ำบนฐานข้อมูลที่มีข้อมูลจริงอยู่แล้ว

ข้อมูลตัวอย่างเก่าที่มีปีแบบพุทธศักราช (เช่น 2563) ไม่ควรนำมาใช้งานจริง ข้อมูลที่ใช้งานจริงต้องเป็นปีคริสต์ศักราช โปรดดูหัวข้อ 9

3.2 คอลัมน์ employee.active (V2) สำหรับฐานข้อมูลเดิม

การติดตั้งใหม่ด้วย schema-mariadb.sql มีคอลัมน์ employee.active อยู่แล้ว ไม่ต้องรัน V2 สำหรับฐานข้อมูลที่ย้ายมาจากระบบเก่า ให้ตรวจก่อน หากผลลัพธ์เป็น 0 จึงรัน V2 (สคริปต์ทำซ้ำได้อย่างปลอดภัย)

SELECT COUNT(*) FROM information_schema.columns
WHERE table_schema = 'worktime' AND table_name = 'employee' AND column_name = 'active';

-- ถ้าได้ 0 ให้รัน
mariadb -u <admin_user> -p worktime < database/migrations/V2__employee_active.sql

3.3 สร้างผู้ใช้สิทธิ์จำกัดสำหรับแอปพลิเคชัน (V3)

แก้ไขไฟล์ database/migrations/V3__app_user.sql ก่อนรัน โดยเปลี่ยนรหัสผ่าน CHANGE_ME_STRONG_PASSWORD เป็นรหัสผ่านที่คาดเดายาก และเปลี่ยนโฮสต์ '%' เป็นที่อยู่ของเครื่อง Backend

mariadb -u <admin_user> -p worktime < database/migrations/V3__app_user.sql
ตารางสิทธิ์ที่ให้ worktime_app
employee, worktypeSELECT
employee_has_sidework_history, sidework_history, ot_historySELECT, INSERT, UPDATE, DELETE

หมายเหตุ: ห้ามใช้ root ให้แอปพลิเคชันเชื่อมต่อฐานข้อมูล และแอปไม่แก้โครงสร้างฐานข้อมูลเอง (ddl-auto=none)

4. การติดตั้งและรัน Backend

4.1 Build เป็น executable jar

cd worktime-backend
mvn test        # (ไม่บังคับ) ทดสอบด้วย H2 ไม่ต้องมีฐานข้อมูลจริง
mvn package     # ได้ target/worktime-backend-2.0.0.jar

4.2 กำหนดค่าผ่าน environment variable

Backend อ่านค่าตั้งค่าจาก environment variable เท่านั้น ห้ามเก็บรหัสผ่านในซอร์สโค้ดหรือ git สร้างค่า JWT_SECRET ด้วย:

openssl rand -base64 48

ตัวอย่าง (Linux):

export DB_URL='jdbc:mariadb://db-host:3306/worktime?sslMode=verify-full'
export DB_USERNAME='worktime_app'
export DB_PASSWORD='<รหัสผ่านจาก V3>'
export JWT_SECRET='<ผลลัพธ์จาก openssl rand -base64 48>'
export APP_ADMIN_EMPLOYEE_NOS='C0001,C0002'
export IS_SERVICE_URL='https://cdgisweb.cdg.co.th/iswebservice/isservice.asmx'
export COOKIE_SECURE=true
export APP_ALLOWED_ORIGINS=
export PORT=8080

ตัวอย่าง (Windows PowerShell):

$env:DB_URL = 'jdbc:mariadb://db-host:3306/worktime?sslMode=verify-full'
$env:DB_USERNAME = 'worktime_app'
$env:DB_PASSWORD = '<รหัสผ่านจาก V3>'
$env:JWT_SECRET = '<ค่าสุ่มอย่างน้อย 32 bytes>'
$env:APP_ADMIN_EMPLOYEE_NOS = 'C0001,C0002'
$env:COOKIE_SECURE = 'true'

JDBC URL สำหรับ production ใช้ jdbc:mariadb://<host>:3306/worktime?sslMode=verify-full (driver คือ mariadb-java-client ที่รวมอยู่ใน jar แล้ว) ส่วนการพัฒนาบนเครื่องตัวเองใช้ sslMode=disable เช่น jdbc:mariadb://localhost:3306/worktime?sslMode=disable รายละเอียดตัวแปรทั้งหมดอยู่ในภาคผนวก ก

4.3 รัน Backend

java -jar target/worktime-backend-2.0.0.jar

Backend จะให้บริการที่ http://localhost:8080/workTimeAPI (context path /workTimeAPI) หากต้องการเปลี่ยนพอร์ตให้ตั้ง PORT

4.4 รันแบบพัฒนา (Development)

cd worktime-backend
cp src/main/resources/application-local.properties.example src/main/resources/application-local.properties
# แก้ค่าในไฟล์ (ไฟล์นี้ถูก git ignore)
mvn spring-boot:run -Dspring-boot.run.profiles=local

หมายเหตุ: โปรไฟล์ local ตั้ง secure-cookie=false และใช้ http เพื่อการพัฒนาบนเครื่องตัวเองเท่านั้น ห้ามใช้ใน production

5. การ Build Frontend

cd frontend
npm ci
npm run build

ผลลัพธ์อยู่ที่ frontend/dist/cdg-time-attendance/browser ให้นำทั้งโฟลเดอร์ไปวางที่ root ของเว็บเซิร์ฟเวอร์ (เช่น /var/www/worktime)

sudo mkdir -p /var/www/worktime

การพัฒนา (Development): npm start จะเปิด http://localhost:4200 และ proxy /workTimeAPI ไปที่ http://localhost:8080 ตามไฟล์ proxy.conf.json จึงต้องรัน Backend ที่พอร์ต 8080 ก่อน

npm start

Frontend เรียก API ที่ path /workTimeAPI/api/... เสมอ จึงไม่ต้องแก้ localhost ในซอร์สโค้ด (ต่างจาก v1)

6. การติดตั้งบน Production

6.1 ตั้งค่า nginx (HTTPS + reverse proxy)

ตัวอย่างต่อไปนี้แสดงส่วน location ภายใน server block ที่ตั้งค่า HTTPS (listen 443 ssl, ssl_certificate ฯลฯ) แล้ว

location /workTimeAPI/ {
  proxy_pass http://127.0.0.1:8080;
  proxy_set_header X-Forwarded-Proto $scheme;
  proxy_set_header X-Forwarded-For $remote_addr;
}
location / {
  root /var/www/worktime;
  try_files $uri $uri/ /index.html;
  add_header Content-Security-Policy "default-src 'self'; style-src 'self' 'unsafe-inline'; font-src 'self'; img-src 'self' data: blob:; frame-ancestors 'none'" always;
  add_header X-Content-Type-Options nosniff always;
  add_header Referrer-Policy no-referrer always;
}

หมายเหตุ: Backend ต้องไม่เปิดให้เข้าถึงโดยตรงจากภายนอก (bind/firewall ให้รับเฉพาะ 127.0.0.1 หรือจาก proxy) เพราะระบบเชื่อถือ X-Forwarded-* ควรมี server block พอร์ต 80 ที่ redirect ไป HTTPS

sudo nginx -t
sudo systemctl reload nginx

6.2 รัน Backend เป็น service (Linux systemd)

เก็บ environment variable ในไฟล์ที่จำกัดสิทธิ์ เช่น /etc/worktime/worktime.env:

sudo mkdir -p /etc/worktime /opt/worktime
sudo cp target/worktime-backend-2.0.0.jar /opt/worktime/
sudo useradd --system --no-create-home --shell /usr/sbin/nologin worktime
# สร้างไฟล์ /etc/worktime/worktime.env แล้วจำกัดสิทธิ์
sudo chown root:worktime /etc/worktime/worktime.env
sudo chmod 640 /etc/worktime/worktime.env

ไฟล์ /etc/worktime/worktime.env (รูปแบบ KEY=VALUE ไม่ต้องมี export และไม่ต้องใส่เครื่องหมายคำพูด):

DB_URL=jdbc:mariadb://db-host:3306/worktime?sslMode=verify-full
DB_USERNAME=worktime_app
DB_PASSWORD=...
JWT_SECRET=...
APP_ADMIN_EMPLOYEE_NOS=C0001,C0002
IS_SERVICE_URL=https://cdgisweb.cdg.co.th/iswebservice/isservice.asmx
COOKIE_SECURE=true
APP_ALLOWED_ORIGINS=
PORT=8080
TZ=Asia/Bangkok

ไฟล์ /etc/systemd/system/worktime.service:

[Unit]
Description=Worktime backend
After=network.target mariadb.service

[Service]
User=worktime
EnvironmentFile=/etc/worktime/worktime.env
ExecStart=/usr/bin/java -jar /opt/worktime/worktime-backend-2.0.0.jar
Restart=on-failure
SuccessExitStatus=143

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now worktime
sudo systemctl status worktime
journalctl -u worktime -f

6.3 รัน Backend เป็น Windows service

ใช้เครื่องมือห่อหุ้มเป็น Windows service เช่น WinSW (หรือ NSSM) กำหนดคำสั่งเป็น java -jar worktime-backend-2.0.0.jar และกำหนด environment variable ในไฟล์ตั้งค่าของ service (ส่วน env) โดยจำกัดสิทธิ์อ่านไฟล์เฉพาะผู้ดูแลระบบและบัญชีที่รัน service ตั้งให้เริ่มอัตโนมัติและ restart เมื่อล้มเหลว

ตัวอย่าง WinSW (worktime.xml):

<service>
  <id>worktime</id>
  <name>Worktime Backend</name>
  <executable>java</executable>
  <arguments>-jar C:\worktime\worktime-backend-2.0.0.jar</arguments>
  <env name="DB_URL" value="jdbc:mariadb://db-host:3306/worktime?sslMode=verify-full"/>
  <env name="DB_USERNAME" value="worktime_app"/>
  <env name="DB_PASSWORD" value="..."/>
  <env name="JWT_SECRET" value="..."/>
  <env name="COOKIE_SECURE" value="true"/>
  <log mode="roll"/>
</service>
worktime.exe install
worktime.exe start

nginx บน Windows ใช้การตั้งค่า location เดียวกับหัวข้อ 6.1

7. รายการตรวจสอบด้านความปลอดภัย (Security Checklist)

  • ใช้ HTTPS ทุกส่วน และตั้ง COOKIE_SECURE=true
  • JWT_SECRET ยาวอย่างน้อย 32 bytes สุ่มใหม่ ไม่ซ้ำกับระบบอื่น และเก็บเป็นความลับ (ถ้าเปลี่ยนค่า ผู้ใช้ทุกคนจะถูก logout)
  • ใช้ผู้ใช้ worktime_app (สิทธิ์จำกัด) ห้ามใช้ root และจำกัดโฮสต์ของผู้ใช้ให้เหลือเฉพาะเครื่อง Backend
  • IS_SERVICE_URL เป็น https เพราะมีรหัสผ่านพนักงานวิ่งผ่าน
  • ไฟล์ environment/รหัสผ่านถูกจำกัดสิทธิ์ ไม่อยู่ใน git
  • Backend ไม่เปิดตรงสู่ภายนอก เข้าถึงผ่าน nginx เท่านั้น (firewall ปิดพอร์ต 8080 จากภายนอก)
  • ตั้ง APP_ALLOWED_ORIGINS ว่างเมื่อ Frontend และ API อยู่ origin เดียวกัน
  • APP_ADMIN_EMPLOYEE_NOS ระบุเฉพาะผู้ที่มีสิทธิ์ออกรายงานทั้งองค์กร
  • ตั้ง security header (CSP, X-Content-Type-Options, Referrer-Policy) ตามตัวอย่าง nginx
  • การเชื่อมต่อฐานข้อมูลใช้ TLS (sslMode=verify-full) และรับการเชื่อมต่อเฉพาะจากเครื่อง Backend
  • เปลี่ยนรหัสผ่าน root เดิมของ v1 ที่เคยถูก commit ไว้ใน repository ทันที
  • ตั้งเขตเวลา (time zone) ของเครื่องที่รัน Backend เป็น Asia/Bangkok (เช่น TZ=Asia/Bangkok ในไฟล์ env ของ systemd หรือ -Duser.timezone=Asia/Bangkok) เพราะระบบบันทึก lastUpdate ด้วยนาฬิกาของเซิร์ฟเวอร์
  • ตั้งการสำรองข้อมูลฐานข้อมูลสม่ำเสมอ และเก็บ log ของ Backend/nginx

กลไกในตัวระบบ: Session เป็น JWT ใน cookie HttpOnly; Secure; SameSite=Strict อายุ 8 ชั่วโมง, CSRF แบบ double-submit cookie (XSRF-TOKEN / X-XSRF-TOKEN), ล็อกการเข้าสู่ระบบ 15 นาทีเมื่อผิด 5 ครั้งต่อรหัสพนักงานหรือต่อ IP และข้อความ error ไม่เปิดเผยรายละเอียดภายใน

8. การตรวจสอบหลังการติดตั้ง

  1. ตรวจว่า service ทำงาน: systemctl status worktime และ log ไม่มี error
  2. ตรวจ API ผ่าน nginx ต้องได้ HTTP 204 (คำสั่งด้านล่าง)
curl -i https://<โดเมน>/workTimeAPI/api/auth/csrf
# ผลที่ถูกต้อง: HTTP/1.1 204 และมี Set-Cookie: XSRF-TOKEN=...

9. การปรับปรุงจาก v1 เป็น v2

  • Path ของ API เปลี่ยนเป็น /workTimeAPI/api/... ต้องเปลี่ยน Frontend และ Backend พร้อมกัน ห้ามใช้ Frontend เก่ากับ Backend ใหม่ (หรือกลับกัน)
  • Stack เปลี่ยน: Java 8 -> 21, Maven 3.9+, Angular 9 -> 22, Node.js 22/24, MySQL 5.5 -> MariaDB 12.3 LTS ไม่ต้องใช้ Eclipse, Lombok หรือ Angular CLI แบบ global อีกต่อไป
  • ไม่รองรับการอัปเกรด MySQL 5.5 เป็น MariaDB 12.x แบบ in-place ต้องสำรองด้วย mysqldump ติดตั้ง MariaDB 12.3 ใหม่ แล้ว import ข้อมูล
  • ข้อมูลวันที่ต้องเป็นปีคริสต์ศักราช (ค.ศ.): ข้อมูลตัวอย่างใน dump เก่ามีปี พ.ศ. (เช่น 2563) ข้อมูลที่เป็น พ.ศ. ต้องแปลงก่อน go-live ด้วยคำสั่งแปลงของระบบ (ใช้ปฏิทินพุทธตาม ThaiBuddhistChronology) ห้ามแปลงด้วยการบวกหรือลบตัวเลขปีเอง และต้องสำรองข้อมูลก่อนเสมอ ดูหัวข้อ 9.1
  • เปลี่ยนรหัสผ่าน root ของ MySQL ที่เคยถูก commit ไว้ใน repository v1 และถือว่ารหัสเดิมรั่วไหลแล้ว
  • เปลี่ยนการเชื่อมต่อฐานข้อมูลจาก root เป็น worktime_app (V3)
  • ตั้งค่าแบบ environment variable แทนการแก้ไฟล์ properties

ขั้นตอนแนะนำ:

  1. สำรองฐานข้อมูลเดิมบนเซิร์ฟเวอร์ MySQL 5.5 ด้วย mysqldump (คำสั่งด้านล่าง)
  2. ติดตั้ง MariaDB 12.3 LTS (เครื่องใหม่หรือติดตั้งใหม่) แล้ว import ไฟล์สำรอง
  3. รัน V2__employee_active.sql (ทำซ้ำได้อย่างปลอดภัย)
  4. รัน V4__utf8mb4.sql เพื่อแปลง character set เป็น utf8mb4
  5. ตรวจและแปลงปี พ.ศ. เป็น ค.ศ. ตามขั้นตอนในหัวข้อ 9.1 (สำรองข้อมูลก่อน)
  6. รัน V3__app_user.sql สร้างผู้ใช้ worktime_app (เปลี่ยนรหัสผ่านและจำกัดโฮสต์ก่อน)
  7. หยุดระบบเก่า ติดตั้ง Backend v2 และ Frontend v2 พร้อมกัน
  8. ทำการตรวจสอบตามหัวข้อ 8
mysqldump -u <admin_user> -p --single-transaction --default-character-set=utf8 worktime > worktime-backup.sql
mariadb -u <admin_user> -p -e "CREATE DATABASE worktime CHARACTER SET utf8mb4"
mariadb -u <admin_user> -p worktime < worktime-backup.sql

9.1 การตรวจและแปลงปี พ.ศ. เป็น ค.ศ.

  1. สำรองฐานข้อมูลก่อนเสมอ
  2. รัน database/migrations/V5__check_buddhist_years.sql เพื่อนับจำนวนแถวที่เป็นปี พ.ศ. (สคริปต์นี้ตรวจอย่างเดียว ไม่แก้ข้อมูล)
  3. ตั้งค่า DB_* environment variable แล้วรันโหมด report เพื่อดูตัวอย่างค่าเดิม -> ค่าใหม่
  4. รันโหมด apply เพื่อแปลงทั้งหมดใน transaction เดียว โดยใช้ปฏิทินพุทธ (ThaiBuddhistChronology) คำสั่งนี้ไม่เริ่มเว็บเซิร์ฟเวอร์
  5. รัน V5 ซ้ำ ผลต้องเป็น 0
java -jar worktime-backend-2.0.0.jar --app.maintenance.fix-buddhist-years=report
java -jar worktime-backend-2.0.0.jar --app.maintenance.fix-buddhist-years=apply

หมายเหตุ: ห้ามแปลงปีด้วยการบวกหรือลบตัวเลขเอง ให้ใช้คำสั่งข้างต้นเท่านั้น รายละเอียดดู database/MIGRATION-MariaDB.md (ขั้นตอนที่ 6)

หมายเหตุ: รายละเอียดครบถ้วนของการย้ายข้อมูล ดูที่ database/MIGRATION-MariaDB.md (ตรวจลำดับและคำสั่งที่นั่นก่อนลงมือจริง) หากขัดแย้งกับคู่มือนี้ให้ยึดเอกสารดังกล่าว

10. การแก้ไขปัญหาเบื้องต้น (Troubleshooting)

อาการสาเหตุที่พบบ่อยวิธีแก้
401 ทุกคำขอ / เข้าสู่ระบบแล้วถูกเด้งกลับcookie เป็น Secure แต่เข้าผ่าน http ทำให้เบราว์เซอร์ไม่ส่ง cookieใช้ HTTPS (แนะนำ) หรือเฉพาะตอนพัฒนาบน http://localhost ตั้ง COOKIE_SECURE=false
403 ตอนบันทึกข้อมูลcookie XSRF-TOKEN ถูกบล็อก หรือ Frontend กับ API ต่าง originเสิร์ฟ Frontend และ API ใน origin เดียวกันผ่าน nginx; ตรวจ GET /workTimeAPI/api/auth/csrf; หากจำเป็นต้องต่าง origin ให้ตั้ง APP_ALLOWED_ORIGINS
502 ตอนเข้าสู่ระบบBackend ติดต่อ IS Web Service ไม่ได้ตรวจ IS_SERVICE_URL, DNS, firewall/proxy ขาออก และใบรับรอง https ของปลายทาง
Backend ไม่เริ่ม: "JWT_SECRET must be set"ไม่ได้ตั้ง JWT_SECRET (หรือสั้นกว่า 32 bytes)ตั้ง JWT_SECRET ด้วย openssl rand -base64 48 และตรวจว่า service ได้รับ environment (EnvironmentFile)
Backend เชื่อมต่อฐานข้อมูลไม่ได้ (Access denied / Communications link failure)DB_URL/DB_USERNAME/DB_PASSWORD ผิด, โฮสต์ของผู้ใช้ไม่ตรง, firewall, MariaDB ไม่ทำงานตรวจค่าตัวแปร ทดสอบด้วย mariadb -h <host> -u worktime_app -p และตรวจโฮสต์ใน V3
Table/Column ไม่พบ (เช่น employee.active)ยังไม่ได้รัน schema-mariadb.sql (หรือ V2 กรณีฐานข้อมูลเดิม)ทำตามหัวข้อ 3.1-3.2 (แอปไม่แก้ schema เอง)
Port 8080 ถูกใช้งานอยู่ (Port already in use)มีโปรแกรมอื่นหรือ Backend ตัวเก่ายังทำงานหยุดโปรแกรมเดิม หรือตั้ง PORT เป็นพอร์ตอื่นแล้วแก้ proxy_pass ให้ตรงกัน
เข้าสู่ระบบไม่ได้หลังผิดหลายครั้งระบบล็อก 15 นาที เมื่อผิด 5 ครั้งรอ 15 นาที แล้วลองใหม่
ผู้ใช้ทุกคนถูก logoutเปลี่ยน JWT_SECRET หรือ session ครบ 8 ชั่วโมงเป็นพฤติกรรมปกติ ให้เข้าสู่ระบบใหม่
หน้าเว็บ refresh แล้ว 404nginx ไม่มี try_files ไป /index.htmlใช้ location / ตามหัวข้อ 6.1

ภาคผนวก ก: ตัวแปร Environment (Environment Variables)

ตัวแปรจำเป็นค่าเริ่มต้นตัวอย่าง / คำอธิบาย
DB_URLควรตั้งjdbc:mariadb://localhost:3306/worktime?sslMode=verify-fulljdbc:mariadb://db-host:3306/worktime?sslMode=verify-full
DB_USERNAMEต้องตั้ง-worktime_app (ห้ามใช้ root)
DB_PASSWORDต้องตั้ง-รหัสผ่านของ worktime_app
JWT_SECRETต้องตั้ง-อย่างน้อย 32 bytes เช่น openssl rand -base64 48 (เปลี่ยนแล้วทุกคนถูก logout)
APP_ADMIN_EMPLOYEE_NOSควรตั้ง(ว่าง)C0001,C0002 รหัสพนักงานที่ออกรายงานทั้งองค์กรได้
IS_SERVICE_URLควรตั้งhttps://cdgisweb.cdg.co.th/iswebservice/isservice.asmxควรเป็น https เพราะมีรหัสผ่านวิ่งผ่าน
COOKIE_SECUREไม่บังคับtruefalse เฉพาะพัฒนาบน http://localhost
APP_ALLOWED_ORIGINSไม่บังคับ(ว่าง)ว่างเมื่อ Frontend/API origin เดียวกัน ถ้ามีหลายค่าคั่นด้วย comma
PORTไม่บังคับ8080พอร์ตที่ Backend รับ (context path /workTimeAPI)

ค่าคงที่ในไฟล์ application.properties: session-duration 8h, max-login-attempts 5, login-lockout 15m, is-service timeout 15s, ddl-auto=none
